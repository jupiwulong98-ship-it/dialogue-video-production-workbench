# 标准正反打拆组规则 v1（2026-11-02）

## 业务目标与优先级
输入视频，尽可能找出**每一段独立的连续人物交流**；在每段中只输出**一组**适合图生视频的原图 A/B。
质量优先于凑数量。当前严格限定标准正反打，不接即梦，不做拼接，也不做配音/唇形同步。

## 两阶段语义
1. **先找连续对话片段：** 分批查看全部保留的候选视频帧，发现人物交流，记录起止范围和人物身份锚点；把同一交流中多次 A/B 切换的重复提议合并。不同场景/时间的独立交流不合并。同场不同人物组合的独立交流分开。
2. **再挑最优 A/B：** 在片段时间范围内跨多个镜头寻找候选，使用两张人物锚点防止身份错换；最终二次验证只返回一对合格镜头。片段很长时有候选数量上限（24 张），不保证最佳帧一定入选。

## 明确通过
- 同一段连续交流中两个**不同真人**的独立镜头，构成标准正反打；A/B **不能取同一镜头**。
- 两侧人物脸部可见，优先正脸或小角度侧脸、中近景、无遮挡、自然表情、清晰、字幕不挡脸。
- A/B 仍是原片提取的完整尺寸画面，保留来源秒数、原片不被改动。
- 同一人物对反复切换只输出一组；隔开后形成新的独立对话可另起一组。

## 自动排除（不交给客户人工补选）
- 只有同框、只有单人镜头、没有独立反打；同一个人两张表情或两个角度冒充 A/B。
- 严重挡脸、背影、过度侧脸、过渡模糊、多人群像，找不到另一侧合格画面。
- 参与人物身份不确定、不同场景的镜头拼在一起、缺乏交流关系证据。
- 模型返回空 pairs 或标记 needs_review=true，一律跳过，不进入客户需要操作的“待确认”列表。

每个经过 A/B 二次复核的片段写入 `dialogue_segments`：
`index/start_seconds/end_seconds/anchor_a/anchor_b/status`；
排除时另存 `reason` 到 `excluded_dialogues`。
这份记录用于审计失败候选，并**不等于视频所有真实对白的清单**。

## 非目标、边界与验收
- 第一版不人工修复缺失的反打，不从双人同框自动裁切单人，不生成/拼接视频。
- 界面中保留旧任务和用户手动加组的待确认功能以兼容历史项目，但自动拆解不再给客户生成这类待办。
- 当前用视觉推断交流关系；没有语音识别和完整人工标注，无法保证所有对白场景被发现。
- 验收应使用真实视频人工逐段标注参考集，统计：真实合格段数、自动识别数、漏检数、错误配组、有效组脸部质量和去重错误。**不要只看最终输出组数。**
- 新算法与 Codex 的完整长片实测尚未在这次规则更新中完成，需单独做端到端验收。
