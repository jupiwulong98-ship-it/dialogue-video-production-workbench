# 对话视频生产工作台

Mac 本地验证版。GitHub 仓库标识为 `dialogue-video-production-workbench`，Python 包及现有启动入口名称保持兼容。

当前已实现本地视频导入、逐帧镜头扫描、按连续对话片段归并、从每段挑选最佳 A/B 正反打、人工换图与提示词保存、矩形区域 LaMa 修复及分类图片导出。按最新要求，**即梦暂不接入，当前版本不生成视频**。Windows 适配尚未开始。

## 打开与使用

双击本目录的 **对话视频工具.app**，或 **启动Mac工具.command**。当前 Mac 应用为开发验证入口，依赖本项目目录及 `.venv`、`.tools`，请保留它们的相对位置；它不是可直接发给客户的独立安装包。

1. 点击“导入视频”，选择本机文件。原视频保留原位，不覆盖。
2. 可填写分析起止秒数；结束时间留空表示分析整部视频。
   已扫描的项目可直接点击“全部镜头”，在软件内浏览所有镜头代表图，点击放大并用上一/下一镜头切换；浏览不会启动 AI 分析。
3. 点击“开始拆解”。程序逐帧扫描镜头、提取候选，先由 Codex 分批找连续交流的候选片段（附两个人物锚点），跨批合并同段重复，再从该片段不同镜头选一组最佳 A/B，准备原尺寸截图。界面直接显示每组两张的结果，候选帧默认收起。
4. 每段连续交流仅输出一组最佳正反打：在整段候选镜头中选两位人物清晰、无遮挡的正脸。缺少独立视角或脸部不可用的候选段自动排除，不会进入待确认让客户逐一补选。分析记录仍保留这些被排除段的时间与原因。旧项目及手动新建组的“待确认”界面保留兼容。这些是视觉配组，不代表实际说话人或口型识别。
5. 不满意时点击“更换截图”，选 A 或 B，再点候选帧。两侧不能使用同一帧。更换后该组进入待确认，点击“确认这组截图”后回到结果列表。候选每页 32 张，可横向滚动或翻页；左侧 ＋ 可手动配组。
6. 在右侧填写每组提示词，失焦自动保存，也可点击顶部“保存”。切组、切项目及导出前会等待保存完成。当前只保存，不提交即梦。
7. 如需修复，选择 A 或 B，点击右侧圈选按钮，在原图上框选区域并执行本地 LaMa。完成后可通过“查看原图 / 查看修复图”对照。
8. 勾选要交付的组，点击“导出图片组”，选择输出位置。每次新建独立目录，不覆盖旧版。

已扫描项目的时间范围固定；更换范围时将视频导入为新项目。处理中请保持软件打开，原视频不要移动或修改。成功的识别、去重与二次复核结果会按新版本的缓存键缓存；断网、额度不足或重启后点击“继续拆解”，复用本版本已完成步骤。未完成的在途请求可能需要重新执行。额度不足时不会自动重试或切换付费服务。

默认让 Codex 查看全部候选帧，优先覆盖完整对话；试验过的精简采样出现候选遗漏，因此没有启用。该规则不等于把视频每一帧都发给模型：每一帧由本地检测器扫描，模型只看保留的候选画面。

长片需要足够的 Codex 账号额度。已有约 92 分钟视频的完整本地扫描实测，但尚未完成约两小时真实电影的全片语义配组验收，处理时间和准确率不能据短片测试保证。详见 [批量截图验证记录](docs/批量截图验证记录_20261102.md)。

界面布局参考 [Spacedrive](https://github.com/spacedriveapp/spacedrive) 与 [InvokeAI](https://github.com/invoke-ai/InvokeAI)，未复制上游代码、未引入其框架或在线资源。

## 标准正反打筛选规则（2026-11-02）

- **先对话片段，后 A/B：** 按连续交流与参与人物划分，不按镜头切换拆组。同一段 A/B/A/B 反复切换，只保留一组；新的独立对话段即使人物相同也另出一组。
- **优先可生成质量：** 两张都应有不同真人的清晰脸部、明确单人主体、近正面、少遮挡、稳定构图；优先从整个片段而不是仅初始锚点镜头中挑选。
- **不凑图、不强制人工：** 缺另一侧独立视角、严重遮脸、群像、背影或交流关系不明的候选段自动排除，时间范围与原因写入项目 `dialogue_segments` / `excluded_dialogues` 和统计报告，不进入待确认。
- **覆盖边界：** 当前依赖画面候选与 Codex 视觉理解，不做语音转写或口型识别；完全没被识别为候选的对话不能凭本报告推算漏检率，更不能保证任意长片 100% 找全。
- 详细定义见 [标准正反打拆组规则](docs/标准正反打拆组规则_v1.md)。

## 导出内容

每组一个文件夹，包含 A/B 原始 PNG、已完成的修复 PNG、A/B 用于生成的 PNG、相应遮罩及提示词。根目录的 `manifest.json` 记录原片时间点、选图及处理版本。

尚未修复的图片按原图导出，清单会标为 `original`；不会将未处理图片标成“已去水印”。导出回到原片提取完整尺寸，候选缩略图不代替正式图片。

## 运行环境

- 当前实测 macOS 26.2 / Apple Silicon ARM64，独立 Python 3.11 虚拟环境。
- Codex 使用本机应用内有效 CLI 路径，不修改全局 MkBoard 桥接，也不复制登录凭据。
- FFmpeg、FFprobe 用于读取视频及提取完整尺寸截图。
- LaMa TorchScript 模型使用 CPU，局部修复效果需要看图检查；没有自动接入在线图片服务。
- 如需改路径，在项目根目录建立 `settings.local.json`，可配置 `codex`、`ffmpeg`、`ffprobe`、`model`、`data`。不要在该文件写入账号令牌。

运行环境检查：

```sh
.venv/bin/python -m dialogue_tool doctor
```

测试：

```sh
.venv/bin/python -m pytest -q
```

从源码准备本地开发环境：

```sh
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e '.[test,repair,desktop]'
```

还需本机安装 FFmpeg / FFprobe、可用的 Codex CLI，并由使用者本人完成账号登录。需要本地修复时，将 [LaMa TorchScript 模型](https://github.com/enesmsahin/simple-lama-inpainting/releases/download/v0.1.0/big-lama.pt) 放入 `.tools/models/big-lama.pt`，或通过 `settings.local.json` 的 `model` 指定路径。模型 SHA256 应为 `7ba7aa7ac37a4d41fdbbeba3a2af7ead18058552997e3a3cd1a3b2210c9e6b4c`。

源码环境可直接运行 `.venv/bin/python -m dialogue_tool desktop`，或双击 **启动Mac工具.command**。Mac 应用启动壳由 py2app 的 alias 模式生成：先在虚拟环境安装 `py2app`，再创建并进入独立的 `.mac-build` 目录，运行 `../.venv/bin/python ../setup_mac.py py2app -A`，避免业务包的依赖元数据影响构建；生成的应用位于 `.mac-build/dist/`，使用时仍依赖源码及虚拟环境。

详见 [Mac 验证记录](docs/Mac验证记录.md)。已用真实开放电影完成局部配组、界面操作、CPU 修复与导出。整部测试片已完成本地扫描，**没有对整部电影完成所有 Codex 配组验收**，也未验证任意电影的准确率。
